# Learning proposal: Honor JSON paths in simulation reports

Status: proposed; human review and merge required.

## Observed problem

The balance verifier writes Markdown to .json report paths, causing casual-game gate invalid JSON failures.

## Proposed improvement

Serialize structured reports for .json output paths; retain Markdown defaults, verdicts, and gate enforcement.

Base commit: `0ba1407524f72af534c05e569f42d6afdd1d3bde`

## Source evidence

### fgws-simulation-json-evidence.txt

SHA-256: `6f7c12521b5cea037a686676a842c2b4dafb9b7f6a17beaed03d2f40ccc3ed95`

    Observation: simulate_balance.py --model report --config .claude/docs/templates/balance-configs/bot-report-example.json --report <temp>/simulation-500.json --no-stamp exits 0 but the file starts with "# Balance Report — Selftest Peg Clear". It is Markdown, not JSON. The static gate parses every design/balance/*.json as JSON and rejects this output. The user reported invalid JSON for simulation-500.json and simulation-preproduction.json; neither original artifact is present locally, so this reproduces a matching failure mechanism, not an inspection of those files. Remedy: choose structured JSON output for a .json report path, keep default Markdown and verdicts, and verify output with the existing gate. Ensure the built-in casual-config metric uses casual wording so compliant JSON reports do not trigger their own vocabulary scan.
