Add conditional Web input guidance to trace event ordering and strong pointer-map roots; verify a narrowly scoped finished-touch workaround while preserving active touch, mouse, pen, up/cancel and the pinned toolchain.

    Same profile build and Settings/Back touch workload, ten warm cycles plus thirty measured cycles, forced GC. Audio was already fixed. Flutter 3.27 / Chrome 153.

    1. Pointer-leave recreation. Before, _PointerDeviceState and _ButtonSanitizer each grow 20 → 80. Strong root paths in route-memory-fixed-profile/retaining-paths.json point respectively to engine global pointer-state and adapter sanitizer maps. Installed pointer_binding.dart removes touch state on up, then its unconditional leave handler ensures a sanitizer and converts a buttons=0 leave into hover. A raw DOM probe records ten distinct touch down/up/leave sequences. A browser capture filter suppresses only pointerleave for finished touch (buttons=0), preserving active touch, mouse, pen, up and cancel. After: both 0 → 0 in route-memory-input-fixed-profile/object-counts.json. This is a pinned engine-specific workaround, not a general pointerleave ban or SDK upgrade.

    2. Accepted tap arena entries. Before GestureArenaEntry grows 10 → 40, rooted through the mounted menu RawGestureDetector/TapGestureRecognizer._entries map. Arena default acceptance removes its arena but leaves the recognizer entry in Flutter 3.27. A GameButton-scoped TapGestureRecognizer calls normal acceptGesture and then resolvePointer for the accepted entry; the resolved arena safely ignores the second resolution. After: GestureArenaEntry 0 → 0; nine controls and recognizers remain nine. Standard gesture competition and canceled drags are preserved. FocusableActionDetector and explicit Semantics.onTap preserve keyboard and accessible activation.
