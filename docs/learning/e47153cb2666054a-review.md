# Affordability audit review

Observed in the Joker's Jewels Session 3 code review: the control deck computed `balance < stake` inside a builder that listened only to the game state notifier. Bet changes and daily credit claims notified the controller but did not change that state notifier. The HUD listened to balance and bet separately, so the control could display stale affordability. The game was corrected by listening to the controller.

The existing UI audit D10 checks that insufficient funds are handled before an action. It does not test the transition from insufficient to sufficient (or back) on the same screen. D11 adds this dynamic check immediately beside D10 and asks for both visible feedback and tap behavior. It permits any implementation that observes all dependencies. The check applies to wager-based actions that display affordability, not every control. No RNG, balance, payout or compliance rule changes.

Validation review: D11 sits in Category D, complements D10 without duplicating it, names the bet/credit transitions that failed, and tests the visible label, enabled state and actual action. The existing table structure remains intact.
