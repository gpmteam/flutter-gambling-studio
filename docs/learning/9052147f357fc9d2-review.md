# Route width audit review

- The existing mobile contract already requires full-bleed phone screens. B16 checked the host phone column, but the runtime proof listed only gameplay captures; it could miss a menu whose root shrink-wrapped inside that column.
- B17 now checks the root and background of each route against both phone edges and names the Flutter `Scaffold.body` loose-constraint failure that produced the observed strip. It directs the fix to the route root without changing the phone-column contract.
- The minimum runtime proof now includes splash and menu at the canonical and short-phone sizes, so a clean console and a full-width gameplay screen cannot alone approve the menu.
- Scope is guidance only. This proposal does not change application code, visual thresholds, RNG, math, compliance, or the existing requirement to inspect all four portrait sizes.
